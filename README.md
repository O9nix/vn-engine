# VNEngine

**VNEngine** — экспериментальный JavaScript-движок для создания визуальных новелл и интерактивных историй.

Проект строится вокруг идеи **минимального ядра и расширяемой plugin-first архитектуры**: ядро отвечает за выполнение истории, а игровые механики и визуальное поведение реализуются отдельными плагинами.

## Основная идея

VNEngine разделяет выполнение истории и её игровые механики.

Ядро отвечает за:

* загрузку проекта;
* переход между узлами истории;
* ожидание и продолжение выполнения;
* регистрацию обработчиков типов узлов;
* события жизненного цикла истории.

Плагины отвечают за конкретные возможности игры:

* диалоги;
* повествование;
* фон;
* ожидание;
* выборы;
* состояние игры;
* условия;
* и другие механики, которые могут появиться позже.

Это позволяет не превращать ядро в набор знаний обо всех возможных игровых механиках.

## Архитектура

Упрощённо система выглядит так:

```text
Project
   │
   ▼
  VN ──────────── EventBus
   │
   │
   ▼
PluginManager
   │
   ├── StatePlugin
   ├── ConditionsPlugin
   ├── DialoguePlugin
   ├── NarrationPlugin
   ├── BackgroundPlugin
   ├── WaitPlugin
   └── ChoicePlugin
```

### VN

`VN` — исполнитель истории.

Он не знает, что такое диалог, выбор, состояние или условие. Для него существует только последовательность узлов и зарегистрированные обработчики их типов.

Обработчик узла получает контекст:

```js
{
    wait(),
    resume(),
    goto(nodeId)
}
```

### Project

`Project` является единым источником данных игры.

В нём находятся:

* сцены;
* узлы;
* конфигурация;
* ресурсы;
* начальные данные проекта.

Runtime-состояние при этом хранится отдельно от `Project`.

### PluginManager

`PluginManager` устанавливает плагины и предоставляет им единый API.

Плагины могут предоставлять собственный публичный API другим плагинам:

```js
api.plugins.state.api.get();
api.plugins.conditions.api.evaluate(condition, state);
```

Таким образом, взаимодействие между плагинами происходит через явно определённые публичные интерфейсы.

### EventBus

`EventBus` используется для событий и фактов, происходящих в системе.

Например:

```js
story:loaded
node:start
story:end
```

События не являются системой навигации. Переходы между узлами выполняются самим `VN`.

### BlockManager

`BlockManager` управляет визуальными блоками, создаваемыми плагинами.

Блок содержит:

```js
{
    id,
    type,
    channel,
    state,
    element,
    data,
    meta
}
```

Это позволяет разным плагинам работать с визуальными элементами, не зная внутренней реализации друг друга.

## Плагины

Плагин имеет минимальный контракт:

```js
export const ExamplePlugin = {
    name: 'example',

    install(api) {
        return {
            api: {
                // публичный API плагина
            },

            cleanup() {
                // освобождение ресурсов
            }
        };
    }
};
```

Плагин может:

* регистрировать типы узлов;
* создавать визуальные блоки;
* подписываться на события;
* предоставлять публичный API;
* использовать API других плагинов.

Игровая механика не должна попадать в ядро без необходимости.

## Состояние игры

Runtime-состояние принадлежит `StatePlugin`.

Начальные значения могут находиться в конфигурации проекта:

```js
const project = new Project({
    config: {
        state: {
            health: 3,
            money: 100
        }
    }
});
```

После загрузки проекта `StatePlugin` получает начальные данные через событие:

```text
Project
   │
   │ story:loaded
   ▼
StatePlugin
   │
   ▼
runtime state
```

Другие плагины работают с состоянием через его публичный API:

```js
const state =
    api.plugins.state.api.get();

api.plugins.state.api.set(
    'health',
    10
);
```

`Project` и runtime-состояние являются разными сущностями.

## Условия

Проверка игровых условий реализована отдельным `ConditionsPlugin`.

Например:

```js
{
    variable: 'health',
    operator: '>',
    value: 5
}
```

Плагин предоставляет:

```js
api.plugins.conditions.api.evaluate(
    condition,
    state
);
```

На текущем этапе поддерживаются операторы:

```text
==
!=
>
>=
<
<=
```

## Выборы

Выбор является отдельным типом узла и реализуется `ChoicePlugin`.

Один логический вариант может иметь несколько вариантов результата в зависимости от состояния:

```js
{
    id: 'go',
    variants: [
        {
            condition: {
                variable: 'health',
                operator: '<=',
                value: 5
            },
            text: 'Сначала в больницу',
            goto: 'hospital'
        },
        {
            condition: {
                variable: 'health',
                operator: '>',
                value: 5
            },
            text: 'Пойдём домой',
            goto: 'home'
        }
    ]
}
```

`ChoicePlugin` определяет подходящий вариант через `ConditionsPlugin`, а затем выполняет переход через API ядра:

```js
context.goto(nodeId);
```

## Следующие шаги

Ближайшая архитектурная задача — добавить систему зависимостей плагинов.

Например:

```js
export const ChoicePlugin = {
    name: 'choice',

    dependencies: [
        'state',
        'conditions'
    ],

    install(api) {
        // ...
    }
};
```

`PluginManager` должен будет самостоятельно проверять наличие необходимых плагинов и выдавать понятные ошибки при нарушении зависимостей.

В дальнейшем plugin API может расширяться без необходимости переносить игровые механики в ядро.

## Документация

API проекта документируется непосредственно в исходном коде и генерируется с помощью `apiscribe`.

Исходный код и API-комментарии являются единым источником истины для документации.

## Статус проекта

VNEngine находится в стадии активной разработки.

Архитектура сейчас важнее количества реализованных игровых механик: цель ранних версий — сформировать устойчивое ядро, вокруг которого можно безопасно развивать плагины и инструменты.
