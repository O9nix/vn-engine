VN Engine

JavaScript-движок визуальной новеллы на ES Modules. Движок построен вокруг небольшого Core и расширяется плагинами.

Главный принцип: Core исполняет сценарий, а конкретная игровая механика находится в плагинах.

Архитектура

Project
   ↓
VN (Core)
   ↓
Node Handler
   ↓
Plugin
   ↓
BlockManager / Player / EventBus

Project хранит структуру сценария. VN владеет текущим узлом и навигацией. PluginManager устанавливает плагины и предоставляет им общий API. BlockManager управляет визуальными блоками.

Плагины могут регистрировать новые типы узлов и публиковать собственный API.

Исполнение сценария

  1. Создаётся Project.
  2. Создаётся VN.
  3. Плагины регистрируются через PluginManager.use().
  4. game.loadProject(project) начинает выполнение с первого узла первой сцены.
  5. VN находит handler по node.type.
  6. Handler создаёт UI/логику и при необходимости вызывает context.wait().
  7. Продолжение выполняется через context.resume(), context.goto(id) или обычный переход к следующему узлу.

API: VN

Файл core.js. Core отвечает за выполнение сценария.

getBus()

Возвращает EventBus экземпляра VN.

getState()

Текущий runtime-state Core. В целевой архитектуре состояние планируется вынести в StatePlugin.

registerNodeType(type, handler)

Регистрирует обработчик типа узла.

loadProject(project)

Загружает Project и запускает историю с первого узла.

next()

Запускает текущий узел, если VN не находится в ожидании.

Контекст handler

handler(node, {
    wait(),
    resume(),
    getState(),
    goto(nodeId)
});

API: Project

Файл project.js. Project является моделью сценария.

const project = new Project({
    metadata: {},
    scenes: [],
    config: {},
    assets: {}
});

getMetadata()

Возвращает metadata проекта.

getScenes()

Возвращает все сцены.

getScene(id)

Находит сцену по id.

getNode(id)

Находит узел во всех сценах.

getSceneForNode(nodeId)

Возвращает сцену-владельца узла.

getNextNode(nodeId)

Возвращает следующий узел внутри сцены.

getConfig()

Возвращает config.

getAssets()

Возвращает assets.

API: EventBus

Файл events.js.

const off = bus.on('event', payload => {
    console.log(payload);
});

bus.emit('event', data);
off();

on(type, handler)

Подписка на событие. Возвращает функцию отписки.

off(type, handler)

Удаляет обработчик.

emit(type, payload)

Отправляет событие подписчикам.

Правило: EventBus сообщает о фактах. Навигация выполняется через API контекста VN, например context.goto().

API: PluginManager

PluginManager — обязательная точка установки плагинов.

const plugins = new PluginManager(
    bus,
    game,
    player,
    blocks,
    conditions
);

use(plugin)

Устанавливает плагин и вызывает его install(api).

remove(name)

Удаляет плагин и вызывает его cleanup.

has(name)

Проверяет установлен ли плагин.

get(name)

Возвращает исходный объект плагина.

list()

Возвращает имена установленных плагинов.

API плагина

Плагин имеет имя и метод install(api). Install может вернуть публичный API и cleanup.

export const MyPlugin = {
    name: 'my-plugin',

    install(api) {
        return {
            api: {
                hello() {
                    return 'hello';
                }
            },

            cleanup() {
                // очистка
            }
        };
    }
};

Доступ к API другого плагина

const state = api.plugins.state;

state.api.getValue('health');

Имена API не являются глобальными: обращение идёт через конкретное имя установленного плагина.

API: BlockManager

Управляет визуальными блоками, создаваемыми плагинами.

const block = api.blocks.create('dialogue', {
    channel: 'content',
    element,
    data: {},
    meta: {}
});

create(type, options)

Создаёт видимый блок и делает его текущим для channel.

get(id)

Получает блок по техническому id.

getAll()

Все блоки.

getByType(type)

Блоки конкретного типа.

getActiveByChannel(channel)

Видимые блоки канала.

getCurrent(channel)

Текущий блок канала, даже если он скрыт.

show(id)

Показывает блок.

hide(id)

Скрывает блок.

remove(id)

Удаляет DOM и сам блок из менеджера.

Block

{
    id,
    type,
    channel,
    state,
    element,
    data,
    meta
}

API: Player

getPluginLayer()

Возвращает общий DOM-контейнер для плагинов.

registerLayer(name, element)

Регистрирует именованный визуальный слой.

show(name)

Показывает именованный слой.

hide(name)

Скрывает именованный слой.

isVisible(name)

Проверяет видимость слоя.

API: ConditionEvaluator

Файл core/condition-evaluator.js.

conditions.evaluate(condition, state);

Поддерживаются операторы:

==  !=  >  >=  <  <=

Если condition отсутствует, результат — true. В текущей реализации используются == и !=.

Плагины

Текущие плагины проекта:

  • dialogue
  • narration
  • background
  • wait
  • choice
  • state — реализован, но пока не подключён в текущем main.js.

DialoguePlugin

Регистрирует node type dialogue, создаёт Block канала content и вызывает context.wait().

NarrationPlugin

Регистрирует narration, создаёт content-блок и ожидает продолжения.

BackgroundPlugin

Регистрирует background и устанавливает CSS background у document.body.

WaitPlugin

Регистрирует wait. Берёт текущий content-блок, добавляет progress bar и после duration вызывает context.resume().

ChoicePlugin

Регистрирует choice, создаёт overlay-блок с кнопками и выбирает подходящий variant по условию.

{
    id: 'go',
    variants: [
        {
            condition: {
                variable: 'health',
                operator: '<=',
                value: 5
            },
            text: 'Сначала в больницу',
            goto: 'hospital'
        },
        {
            text: 'Пойдём домой',
            goto: 'home'
        }
    ]
}

Variant выбирается при отображении Choice. При выборе кнопки выполняется goto, если он задан; иначе вызывается context.resume().

StatePlugin

Плагин уже существует в проекте и предоставляет:

api.get()
api.getValue(name)
api.set(name, value)
api.update(values)

Пример:

api.plugins.state.api.set('health', 10);

const health =
    api.plugins.state.api.getValue('health');
Текущий статус: StatePlugin пока не подключён в main.js. Кроме того, VN всё ещё содержит собственный #state. Следующий этап — сделать StatePlugin единственным владельцем runtime state.

                        {
                            id: 'go',
                            variants: [
                                {

                                {
                                    text: 'Пойдём домой',

    ]
});

Модель Choice

Option — логический ответ игрока. Variant — конкретное представление и действие, подходящее текущему состоянию.

Choice
└── option
    └── variants
        ├── condition
        ├── text
        └── goto
