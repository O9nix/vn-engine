# Versioning

VN Engine использует Semantic Versioning (`MAJOR.MINOR.PATCH`).

## Правила

- **PATCH** — обратно совместимое исправление без изменения публичного API.
- **MINOR** — новая обратно совместимая функциональность или расширение API.
- **MAJOR** — обратно несовместимое изменение публичного API.

Пока проект находится в `0.x`, API считается нестабильным. Мы всё равно фиксируем каждую релизную точку, чтобы можно было восстановить состояние кода и документации.

## Источники версии

Основной источник версии проекта — `package.json`.

`package-lock.json` должен содержать ту же версию корневого пакета.

Файл `VERSION` содержит удобную текстовую копию текущей версии.

## Документация версий

Для каждой релизной версии создаётся snapshot:

```text
 docs/versions/<version>/
 ├── api.md
 └── overview.md
```

Snapshot не изменяется после фиксации версии.

## Git tags

Каждой релизной версии соответствует Git tag:

```text
v0.1.0
v0.2.0
...
```

Таким образом:

- Git хранит историю исходного кода;
- `docs/versions/` хранит исторический API;
- `docs/changelog.md` описывает изменения между версиями.
