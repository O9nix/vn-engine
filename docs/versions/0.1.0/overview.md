# VN Engine 0.1.0 — состояние проекта

Дата фиксации: 2026-10-06

## Назначение

VN Engine — JavaScript-движок визуальной новеллы на ES Modules.

Главный принцип версии 0.1.0:

> Core исполняет сценарий, а конкретная игровая механика находится в плагинах.

## Основные компоненты

- `VN` — выполнение сценария и навигация между узлами.
- `Project` — источник истины для структуры проекта и сценария.
- `EventBus` — коммуникация через события.
- `Player` — визуальный корень и управление named layers.
- `BlockManager` — управление визуальными блоками.
- `PluginManager` — установка плагинов и предоставление plugin API.
- `ConditionEvaluator` — вычисление условий.
- Plugins — конкретная игровая функциональность.

## Плагины

В проекте присутствуют:

- DialoguePlugin
- NarrationPlugin
- BackgroundPlugin
- WaitPlugin
- ChoicePlugin
- StatePlugin

При этом в 0.1.0 `StatePlugin` уже реализован, но ещё не подключён в текущей сборке `main.js`. Runtime state фактически продолжает храниться внутри `VN`.

## Навигация

`VN` является владельцем текущего узла и переходов.

Поддерживаются:

- последовательный переход к следующему узлу;
- `context.goto(nodeId)`;
- ожидание через `context.wait()` / продолжение через `context.resume()`;
- `end: true`;
- завершение при отсутствии следующего узла.

## BlockManager

Визуальные блоки имеют структуру:

```js
{
    id,
    type,
    channel,
    state,
    element,
    data,
    meta
}
```

Каналы в текущей архитектуре используются как логические группы, например `content`, `overlay`, `background`.

## Условия

Поддерживаются операторы:

- `==`
- `!=`
- `>`
- `>=`
- `<`
- `<=`

Отсутствующее условие считается истинным.

## Важные ограничения версии

- Runtime state ещё не вынесен полностью в `StatePlugin`.
- Зависимости плагинов ещё не проверяются автоматически `PluginManager`.
- `FlowResolver` присутствует в дереве проекта, но не используется в текущем runtime-потоке.
- API версии 0.x считается нестабильным.
