# VNEngine — Roadmap

Дорожная карта сохраняет исходную логику проекта, но разбивает крупные релизы на небольшие контрольные точки. Номер версии обозначает этап готовности, а не обязательный календарный срок.

---

## 0.1.2 — Движок

**Цель:** Создать стабильное ядро для сценариев, плеера и будущих плагинов.

### Что появляется
- Сценарии и команды: text, wait, choice, jump, setvar, setflag.
- State: переменные, флаги и общее состояние проекта.
- EventEmitter для событий движка, команд, состояния и жизненного цикла.
- Capabilities API для регистрации и получения сервисов.

### Подпункты
- Реализовать VNEngine с очередью команд и состоянием.
- Поддержать несколько экземпляров: редактор, preview iframe и плеер.
- Добавить snapshot/restore, валидацию сцен и уровней логирования.
- Покрыть переходы, переменные и восстановление состояния тестами.

### Критерии готовности
- Простой сценарий запускается и проходит до конца.
- Состояние сохраняется и восстанавливается без потери прогресса.
- Ошибки формата обнаруживаются с понятным сообщением.

### Зачем
Это общий технический фундамент для всех последующих подсистем.

- Манифест с именем, версией, зависимостями и capabilities.
- Проверка совместимости с API движка.
- Изоляция ошибок отдельного плагина.

### Подпункты
- Определить формат манифеста и правила версионирования.
- Проверять зависимости, порядок инициализации и отсутствующие capabilities.
- Добавить включение/отключение и журнал ошибок.
- Создать пример минимального плагина и тесты жизненного цикла.

### Критерии готовности
- Тестовый плагин подключается через единый интерфейс.
- Ошибки не останавливают весь движок.
- Контракт плагина задокументирован.

### Зачем
Сначала фиксируется контракт плагина; реестр и установка появятся отдельными этапами.

## Дополнительные рекомендации по порядку работ

- **Движок и плеер (0.1.x):** сначала стабилизировать состояние, события и API, затем последовательно добавлять медиа и библиотеку ассетов.
- **AST (0.2.x):** сначала структура и парсер, затем обратное преобразование, ассеты и диагностика.
- **Редактор (0.3.x):** сначала просмотр и навигация по графу, затем редактирование, панель свойств и Undo/Redo.
- **Плагины (0.4.x):** отдельно вести API, песочницу, сервер загрузки, проверки, сервис установки и каталог. Это разные компоненты.
- **Публикация (0.5.x):** сначала сохранение и проверка проекта, затем модерация. Одобренная версия хранится как неизменяемый снимок.
- **Каталог и чтение (0.6.x):** публично показывать только разрешённые к публикации версии.
- **Внешняя платформа (0.7.x):** сначала добиться корректного запуска, затем отдельно стабилизировать интеграцию.
- **Параллельная разработка:** редактор и сервер плагинов можно разрабатывать параллельно после согласования формата проекта и публичного API.

Переходить к следующему этапу стоит после выполнения критериев готовности предыдущего этапа в соответствующей ветке. Необязательно синхронизировать номера релизов между независимыми ветками разработки.
